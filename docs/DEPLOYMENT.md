# SYSCORE — запуск и передача

## Что построено

Главная состоит из пяти разделов: идентичность компании, выбор задачи, основатель, обучение, связь. Подробности вынесены на `/services`, `/company`, `/education`, `/contact`. Четыре пункта меню, мобильная навигация, состояния ошибок и загрузки, sitemap, robots и Open Graph.

Контент: `content/site-content.ts`. Параметры адреса сайта: `config/site.ts`. Пустой, некорректный или не-HTTP URL не ломает сборку; резерв — текущий production-адрес `https://syscore-blond.vercel.app`.

Опубликованы сведения из 11 предоставленных документов: PhD и 10 курсов/сертификатов. Это квалификация основателя, не сертификация SYSCORE. Исходные PDF, подписи и номера удостоверений не загружаются в GitHub. Coursera-ссылки взяты из документов; их независимая онлайн-аутентификация не выполнялась. Курс Ethical Hacking не представлен как CEH.

Услуги и обучение обозначены как планируемые. Официальные партнёрства, активный SOC, гарантии реагирования, клиентские кейсы и статистика не заявляются.

## Локальный запуск

Node.js 22, npm и файл `.env.local` на основе `.env.example`:

```sh
npm ci
npm run dev
npm run lint
npm run build
```

Для локальной проверки собранного приложения можно использовать `npm run start`. Для самостоятельного production-развёртывания используйте standalone-образ ниже. `next start` предупреждает о standalone; Docker запускает правильный `server.js`.

## Сервер обращений

`POST /api/leads`: Zod-проверка на клиенте и сервере, согласие, honeypot, проверка Origin, предел тела 8 КиБ, ограничение 5 обращений на 10 минут через общий Redis. При неисправности ограничителя отправка прекращается. Процессный счётчик не используется.

Доставка — серверный модуль `lib/leads/delivery.ts`. Telegram вызывается без Markdown/HTML, со временем ожидания; успешное состояние возвращается только после подтверждения API Telegram. Контакты и тела обращений не пишутся в журналы приложения. Возможные сетевые ошибки после доставки могут привести к повторной заявке: гарантия exactly-once не заявляется.

Это доставка в inbox, **не CRM и не база заявок**. Автономного долговременного хранилища, Supabase, аккаунтов, оплаты и аналитики пока нет. Их нельзя считать подключёнными. Интерфейс доставки выделен в отдельный серверный модуль и может быть заменён на согласованную университетскую систему. Секреты никогда не должны иметь префикс `NEXT_PUBLIC_`.

Для включения нужны:

```dotenv
NEXT_PUBLIC_SITE_URL=https://your-approved-domain.example
TELEGRAM_BOT_TOKEN=
TELEGRAM_CHAT_ID=
RATE_LIMIT_REDIS_URL=
RATE_LIMIT_REDIS_TOKEN=
LEAD_INTAKE_APPROVED=false
```

Redis REST endpoint должен поддерживать JSON-команды, включая EVAL, через HTTPS. Токен должен разрешать только необходимые операции на предназначенном для приложения экземпляре/префиксе.

Пока реальные значения не заданы и `LEAD_INTAKE_APPROVED` не равен `true`, форма отключена, API возвращает 503, доступны телефон и WhatsApp. Перед включением оператор должен утвердить условия обработки, место и сроки хранения, доступ к Telegram, правила удаления и допустимость выбранных провайдеров. Текст `/privacy` и `/personal-data` — техническая информация о состоянии системы, не юридическое заключение. После утверждения обновить его под фактическую схему работы.

Нельзя отправлять доказательства, пароли, секретные материалы или данные третьих лиц. Загрузка файлов намеренно отсутствует. Университетские серверы ещё не подключены.

`/api/security-check` закрыт с 503: прежний прототип допускает риск DNS rebinding. Не включать его без изолированного и проверенного сканирующего сервиса. Незадействованные интерактивные черновики сохранены локально и не добавлены на публичные страницы.

## Vercel

Git push в `origin/main` запускает существующую интеграцию. Build command — `npm run build`, framework — Next.js. Установить канонический `NEXT_PUBLIC_SITE_URL`; для смены этого публичного значения пересобрать проект. Серверные секреты задаются в настройках окружения, не в репозитории. Preview и Production должны иметь согласованный Origin; неизвестные origins отклоняются.

GitHub Actions использует Node 22 и `npm ci`, затем lint и Next build вместо ошибочного webpack-вызова.

## Университет / Google Cloud / другой сервер

```sh
docker build --build-arg NEXT_PUBLIC_SITE_URL=https://your-approved-domain.example -t syscore .
docker run --env-file .env.production -p 127.0.0.1:3000:3000 --restart unless-stopped syscore
```

Образ запускается непривилегированным пользователем. HTTPS завершать на reverse proxy, разрешить вход только через него. Proxy должен перезаписывать X-Forwarded-For реальным адресом клиента, а не доверять присланному заголовку. Ограничить размер тела и время чтения запросов также на proxy. Не выставлять порт приложения напрямую в интернет. `/api/health` отвечает без секретов и не подтверждает доступность внешних интеграций.

Секреты хранить вне образа, TLS и обновления ОС поддерживать отдельно. Redis обеспечивает общий лимит при нескольких экземплярах. После смены домена обновить DNS, сертификат, build argument и переменные окружения; выполнить smoke-тест. Домен `score.com` не проверялся и не приобретался. Название, владелец и конкретный домен требуют подтверждения перед покупкой. Docker-сборка здесь не проверена: Docker отсутствует.

## Проверки

```sh
TEST_DELIVERY_DISABLED=true node scripts/smoke-test.mjs
```

PowerShell:

```powershell
$env:TEST_DELIVERY_DISABLED='true'
node scripts/smoke-test.mjs
```

Для другого адреса задать TEST_BASE_URL и TEST_ORIGIN. Скрипт проверяет страницы, 404, health, отключённый сканер, Origin, тип/размер тела и неверное согласие. Проверку 503 выполнять только на тестовом сервере с выключенной доставкой. Успешная доставка Telegram и распределённый лимит требуют тестового bot/chat/Redis; без них end-to-end отправка не подтверждена. Lighthouse-показатели не измерялись.
